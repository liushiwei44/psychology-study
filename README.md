# 心理咨询师备考台 MVP

这是一个本地优先的刷题网站，针对中国心理卫生协会 2026 年心理咨询师（初级）考试设计。

## 启动

在项目目录运行：

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

然后打开：http://127.0.0.1:4173/

## 当前可用功能

- 从两个 PDF 实际解析出的 9488 道题目（单选 3996、多选 3998、判断 1494）
- 自动质检：4 道源 PDF 内容异常题暂不进入正式练习队列，详见 `data/import_report.json`
- 单选、多选、判断题的结构化题库
- 首刷模式：答案和解析在提交前隐藏
- 把握程度记录：默认“有把握”；首次蒙对 3 天后复查，首次模糊答对 7 天后复查，再次答对后退出复习队列
- 错题自动进入并永久保留在本地错题本；已答对且有把握暂缓自动复习，保留原复习时间和状态
- 每轮最多 10 道到期复习：先错题、再蒙题、再模糊题；同一优先级内按题型轮换，不足就少安排，其余补新题，无到期题直接做新题
- 今日目标 / 每轮总题量可调整（默认 50 题），达到每日目标仍可连续开新一轮
- 单独的复习入口每轮也最多 10 道，无到期题自动转新题
- 全库去重：首刷和模拟过滤可确认的重复副本，原题、旧题号和历史记录全部保留
- 多选、案例摘要单选、案例不定项、单选、判断专项：新题直接练；已做巩固每轮最多10题
- 18个自编案例材料组、108道问题（90道案例单选、18道不定项），非官方真题
- 基础知识 / 专业技能各3套固定120分钟训练卷，按用户截图配置题量与评分，题量分值待官方核验
- 模拟答题卡、跳题改答、刷新恢复、交卷后题型/训练考点/逐题解析报告
- 本地统计和模拟记录
- 可选 GitHub 登录与 Supabase 跨设备同步
- 首次升级自动保存原始本机记录和未完成轮次的快照；学习统计可导出当前记录或升级前备份
- 作答明细、模拟历史不再按 12 条 / 100 条截断；同步保留双方可用历史并防止上传期间的新答案被旧快照覆盖

## 2026-10-13 复习与去重调整

旧版每日刷题每开一轮会再取最多 10 道到期题，独立复习入口则按每日目标取题；首页展示的是到期总量，所以可能看到 20 道或更多。这次统一限制新开的每轮复习最多 10 道，不限制每天的总练习量。已有未完成轮次原样恢复，新规则从下一轮生效。

扫描全部 9488 道原题后，在 7990 道结构合格的核心题中确认 11 个重复副本（单选 1、多选 10），首刷需要覆盖 7979 组；判断题另有 22 个重复副本。去重要求题型、规范化题干、选项内容和正确答案内容一致，能识别仅调换选项顺序的重复。252 组同题干但选项或答案不同的变体继续保留。

多选 1930 和 2120 的题干、选项相同，但源答案分别为 ABCD / ABC，已在界面与报告标为“待人工确认”，未擅自合并或改答案。核对报告见 `data/duplicate_report.json`。运行 `node scripts/audit_duplicates.mjs` 可重新生成，题库本身不改写。

去重仅影响选题，不迁移或合并任何学习记录。同组任意原题做过即视为该组已覆盖；历史错题和蒙题仍按原 ID 保留、可复习，每轮同组只取一道。旧的原题覆盖、正确率口径保留，界面另外显示去重后剩余新题量。

自动备份保存在 `psychology-study-backup-before-20261013`，包含升级前 `psychology-study-progress-v1` 与 `psychology-active-session-v1` 的原始字符串。备份失败或记录格式异常时停止加载，不以空记录覆盖。导出文件包含原始记录，可供恢复核对；旧版早已截断且本机、云端均不存在的明细无法重建。

验证：`node --test tests/*.test.mjs`，覆盖多轮与大题量、复习优先级、去重与原题历史、备份、断点恢复、同步合并及上传期间作答。

## 重新解析 PDF

如果 PDF 更新，可以使用项目提供的导入脚本：

```bash
python3 scripts/prepare_questions.py
```

它会更新：

- `data/questions.json`
- `data/import_report.json`

导入报告会保留缺号和解析异常，不会静默丢题。

## 2026-11-03 专项与分科训练

旧版首刷按原题库顺序排题，单选在多选之前；两科模拟都是60道普通题等权估分，未匹配本次用户截图。现在进入“刷题与专项”可直接开始后面的题型，不必等待单选做完。

| 科目 | 单句型单选 | 案例摘要单选 | 多选 | 案例不定项 | 合计 |
| --- | --- | --- | --- | --- | --- |
| 基础知识 | 50×1分 | 25×1分 | 15×1分 | 5×2分 | 95题 / 100分 |
| 专业技能 | — | 50×1分 | 30×1分 | 10×2分 | 90题 / 100分 |

每科120分钟，训练通过线60分。多选全对1分、非空漏选0.5分、错选0分；案例不定项全对2分，漏选/多选/错选/空答0分。日常专项仍按完全正确记录，模拟部分得分也会记入错题本。

配置见 `data/exam-templates.json`。模板来自用户截图，未在可访问的官方大纲中独立核实题量及分值，不宣称为官方组卷。原PDF没有官方科目标签，模拟对普通题按关键词作训练分科；报告同样明确标出。每套卷在当前题库和模板下稳定，案例池有限，套卷之间会复用同题，保持同一原题ID和作答历史。已开始的模拟保存模板及题目快照，不受重新组卷影响。

新增案例存于 `data/case-exercises.json`，独立建模为材料+问题组，区分单选与不定项。不定项包含一个、两个或多个正确选项。案例为自编教学练习，答案和解析未经官方审定。编写源为 `scripts/build_case_bank.mjs`；发布后修改既有案例应保留ID含义，不可把旧ID挪给另一道题。

已核查官网的考试介绍、大纲页及“模拟”搜索；本次未找到可直接公开下载的官方完整真题或模拟卷。官网资料入口：[考试大纲](https://www.cert-camh.org.cn/#/article?key=kszx&activeIndex=3)、[案例解析等公开课](https://www.cert-camh.org.cn/#/home)。仅借鉴考点范围，不把自编练习宣传成官方样题。

题库盘点为 `data/exam-inventory.json`：原9488题、4道结构异常、33个确认重复副本、252组同题干变体，以及非官方的关键词训练考点分布。原报告未独立记录跨页异常数，本次不重新解析PDF或虚构零异常。运行 `node scripts/audit_exam_inventory.mjs` 可更新盘点。

### 考前安排建议

- 11月3日—20日：优先多选，每天60—80道，再加10—20道案例；到期复习每轮最多10道，按时间拆轮。
- 11月21日—12月4日：穿插六套两科训练，单科留足120分钟；交卷后按错题和考点补缺，不把旧题复做当作新题覆盖。
- 12月5日：按准考证参加两科考试。剩余题量不必机械摊完，优先当前未练题型、错题和案例能力。

## 2026-11-09 到期复习按题型轮换

旧规则按错误次数全局排序，旧单选积压时可能占满10个复习名额，已到期专项错题虽入池却迟迟排不到。现在每日练习、到期复习和错题本复习先过滤今日已做题及同组重复，再在错题、蒙题、模糊题各优先级内按题型轮流取一道，合计仍最多10道。同题型继续优先错误次数多、到期较早的题；某题型不足，其余题型补足。

例如20道错3次的单选与各1道刚错的多选、判断、案例单选、案例不定项都已到期，本轮会选6道单选和这4道专项题；五种题型各有足够到期错题时，各选2道。24小时/3天/7天排期不变，旧轮次原样恢复，新规则从新开轮次生效。所有题目ID、累计、错题、历史、备份和同步数据保留。

验证：`node --test tests/*.test.mjs`，包含旧单选积压、五题型轮换、优先级、今日排除、同组去重、三个复习入口及旧轮次/原记录不变。

## 当前限制

- 截图训练模板的题量分值仍待官方核验；本站训练成绩不代表实际考试成绩。
- 案例为自编练习，案例池有限，不同训练卷之间有重复；未声称提供官方真题。
- 原题知识点/科目只有关键词粗分，未完成逐题人工标注；语义近似题不自动归并。
- 未配置 Supabase 或未登录时，学习记录只保存在当前浏览器；登录后才会同步到用户自己的云端记录。

## 数据存储与分享部署

当前 MVP 是纯静态、本地优先应用，并提供可选的 Supabase 同步：

- `data/questions.json` 和 `data/import_report.json` 随网站文件一起提供，浏览器启动时读取；PDF 不参与运行时加载。
- 你的作答记录、错题、把握程度、模拟历史首先写入当前浏览器的 `localStorage`；配置 Supabase 并登录后，会自动与云端合并并同步。
- 题库 JSON 中包含答案和解析，界面只是“提交前隐藏”；因此当前版本适合个人或小范围分享，不适合作为需要保护答案内容的公开题库。

### 方案 A：GitHub Pages + Supabase（当前推荐）

GitHub Pages 托管静态页面和题库，Supabase 提供 GitHub 登录、数据库和 RLS 权限隔离。完整配置步骤见 [`SUPABASE_SETUP.md`](./SUPABASE_SETUP.md)。

仓库已经包含 GitHub Actions 发布流程。Pages 的发布产物不会包含原始 PDF。

### 方案 B：仅静态托管

把 `index.html`、`styles.css`、`app.js`、`study-rules.mjs`、`study-queues.mjs`、`progress-storage.mjs`、`exam-engine.mjs`、`supabase-sync.js`、`config.js` 和 `data/` 一起上传到 GitHub Pages、Cloudflare Pages、Netlify、Vercel 静态站点或任意 Web 服务器即可。每个使用者拥有独立的本地学习记录，部署和维护成本最低。

### 方案 C：局域网临时分享

在项目目录运行：

```bash
python3 -m http.server 4173 --bind 0.0.0.0
```

然后让同一局域网的设备访问这台电脑的局域网 IP 和 `4173` 端口。仅建议临时使用，不要把端口直接暴露到互联网。

如果要公开分享但不希望用户直接下载答案，需要把答案校验移到服务端，通过“提交后请求结果”的接口返回答案；仅靠前端隐藏不能真正保护答案。

### 推荐的多设备架构

```text
GitHub Pages（静态页面 + 题库）
              │
              ├── Supabase Auth（登录身份）
              └── Supabase Postgres（作答、错题、备注、设置）
                         │
                 RLS：每个用户只能读写自己的记录
```

MVP 目前把一位用户的学习状态存成 `study_states` 表中的一行 JSON，避免过早引入复杂的数据表。浏览器仍保留 `localStorage` 作为离线缓存；登录后按每道题最后作答时间合并本地与云端记录。

GitHub 账号只负责代码仓库和 Pages 部署，不等于网站已经有登录/同步能力。网站登录可以接 Supabase 的邮箱密码、Magic Link 或 GitHub OAuth；前端只使用 Supabase publishable/anon key，绝不能把 service role/secret key 放进静态网站。
