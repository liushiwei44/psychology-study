# 心理咨询师备考台 MVP

这是一个本地优先的刷题网站，针对中国心理卫生协会 2026 年心理咨询师（初级）考试设计。

## 启动

在项目目录运行：

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

然后打开：http://127.0.0.1:4173/

## 当前可用功能

- 从两个 PDF 实际解析出的 9488 道题目（单选 3996、多选 3998、判断 1494）
- 自动质检：4 道源 PDF 内容异常题暂不进入正式练习队列，详见 `data/import_report.json`
- 单选、多选、判断题的结构化题库
- 首刷模式：答案和解析在提交前隐藏
- 把握程度记录：默认“有把握”；首次蒙对 3 天后复查，首次模糊答对 7 天后复查，再次答对后退出复习队列
- 错题自动进入并永久保留在本地错题本；已答对且有把握暂缓自动复习，保留原复习时间和状态
- 每轮最多 10 道到期复习：先错题、再蒙题、再模糊题；不足就少安排，其余补新题，无到期题直接做新题
- 今日目标 / 每轮总题量可调整（默认 50 题），达到每日目标仍可连续开新一轮
- 单独的复习入口每轮也最多 10 道，无到期题自动转新题
- 全库去重：首刷和模拟过滤可确认的重复副本，原题、旧题号和历史记录全部保留
- 基础知识 / 专业技能两个 120 分钟模拟入口
- 本地统计和模拟记录
- 可选 GitHub 登录与 Supabase 跨设备同步
- 首次升级自动保存原始本机记录和未完成轮次的快照；学习统计可导出当前记录或升级前备份
- 作答明细、模拟历史不再按 12 条 / 100 条截断；同步保留双方可用历史并防止上传期间的新答案被旧快照覆盖

## 2026-10-13 复习与去重调整

旧版每日刷题每开一轮会再取最多 10 道到期题，独立复习入口则按每日目标取题；首页展示的是到期总量，所以可能看到 20 道或更多。这次统一限制新开的每轮复习最多 10 道，不限制每天的总练习量。已有未完成轮次原样恢复，新规则从下一轮生效。

扫描全部 9488 道原题后，在 7990 道结构合格的核心题中确认 11 个重复副本（单选 1、多选 10），首刷需要覆盖 7979 组；判断题另有 22 个重复副本。去重要求题型、规范化题干、选项内容和正确答案内容一致，能识别仅调换选项顺序的重复。252 组同题干但选项或答案不同的变体继续保留。

多选 1930 和 2120 的题干、选项相同，但源答案分别为 ABCD / ABC，已在界面与报告标为“待人工确认”，未擅自合并或改答案。核对报告见 `data/duplicate_report.json`。运行 `node scripts/audit_duplicates.mjs` 可重新生成，题库本身不改写。

去重仅影响选题，不迁移或合并任何学习记录。同组任意原题做过即视为该组已覆盖；历史错题和蒙题仍按原 ID 保留、可复习，每轮同组只取一道。旧的原题覆盖、正确率口径保留，界面另外显示去重后剩余新题量。

自动备份保存在 `psychology-study-backup-before-20261013`，包含升级前 `psychology-study-progress-v1` 与 `psychology-active-session-v1` 的原始字符串。备份失败或记录格式异常时停止加载，不以空记录覆盖。导出文件包含原始记录，可供恢复核对；旧版早已截断且本机、云端均不存在的明细无法重建。

验证：`node --test tests/*.test.mjs`，覆盖多轮与大题量、复习优先级、去重与原题历史、备份、断点恢复、同步合并及上传期间作答。

## 重新解析 PDF

如果 PDF 更新，可以使用项目提供的导入脚本：

```bash
python3 scripts/prepare_questions.py
```

它会更新：

- `data/questions.json`
- `data/import_report.json`

导入报告会保留缺号和解析异常，不会静默丢题。

## 当前限制

- 正式考试的每类题型题量/分值仍应以官方大纲和准考证为准，MVP 模拟暂时采用可调整的 60 题等权训练模板。
- 现有 PDF 没有独立、完整的案例分析题库，案例题录入和案例组卷将在下一版加入。
- 题目知识点标签和语义近似题归并尚未完成；仅自动过滤可确认的内容重复。
- 未配置 Supabase 或未登录时，学习记录只保存在当前浏览器；登录后才会同步到用户自己的云端记录。

## 数据存储与分享部署

当前 MVP 是纯静态、本地优先应用，并提供可选的 Supabase 同步：

- `data/questions.json` 和 `data/import_report.json` 随网站文件一起提供，浏览器启动时读取；PDF 不参与运行时加载。
- 你的作答记录、错题、把握程度、模拟历史首先写入当前浏览器的 `localStorage`；配置 Supabase 并登录后，会自动与云端合并并同步。
- 题库 JSON 中包含答案和解析，界面只是“提交前隐藏”；因此当前版本适合个人或小范围分享，不适合作为需要保护答案内容的公开题库。

### 方案 A：GitHub Pages + Supabase（当前推荐）

GitHub Pages 托管静态页面和题库，Supabase 提供 GitHub 登录、数据库和 RLS 权限隔离。完整配置步骤见 [`SUPABASE_SETUP.md`](./SUPABASE_SETUP.md)。

仓库已经包含 GitHub Actions 发布流程。Pages 的发布产物不会包含原始 PDF。

### 方案 B：仅静态托管

把 `index.html`、`styles.css`、`app.js`、`study-rules.mjs`、`study-queues.mjs`、`progress-storage.mjs`、`supabase-sync.js`、`config.js` 和 `data/` 一起上传到 GitHub Pages、Cloudflare Pages、Netlify、Vercel 静态站点或任意 Web 服务器即可。每个使用者拥有独立的本地学习记录，部署和维护成本最低。

### 方案 C：局域网临时分享

在项目目录运行：

```bash
python3 -m http.server 4173 --bind 0.0.0.0
```

然后让同一局域网的设备访问这台电脑的局域网 IP 和 `4173` 端口。仅建议临时使用，不要把端口直接暴露到互联网。

如果要公开分享但不希望用户直接下载答案，需要把答案校验移到服务端，通过“提交后请求结果”的接口返回答案；仅靠前端隐藏不能真正保护答案。

### 推荐的多设备架构

```text
GitHub Pages（静态页面 + 题库）
              │
              ├── Supabase Auth（登录身份）
              └── Supabase Postgres（作答、错题、备注、设置）
                         │
                 RLS：每个用户只能读写自己的记录
```

MVP 目前把一位用户的学习状态存成 `study_states` 表中的一行 JSON，避免过早引入复杂的数据表。浏览器仍保留 `localStorage` 作为离线缓存；登录后按每道题最后作答时间合并本地与云端记录。

GitHub 账号只负责代码仓库和 Pages 部署，不等于网站已经有登录/同步能力。网站登录可以接 Supabase 的邮箱密码、Magic Link 或 GitHub OAuth；前端只使用 Supabase publishable/anon key，绝不能把 service role/secret key 放进静态网站。
